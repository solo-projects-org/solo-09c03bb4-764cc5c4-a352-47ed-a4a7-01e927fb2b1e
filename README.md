# 病区 × 周次 阳性检验安全汇总发布

医院感染控制数据员使用的内部小工具：上传检验 CSV，生成带行列合计的
“病区 × 周次”阳性检验交叉表，按保密规则隐藏小计数值，网页预览后用
**独立登记台账逐号核验**检验来源，核验通过方可确认发布，供研究组查看比较。
FastAPI + SQLite，Docker Compose 一键启动。

## 快速启动

```bash
docker compose up --build
# 打开 http://localhost:8000
```

SQLite 数据库保存在命名卷 `app_data`（容器内 `/data/app.db`），
容器重启/重建后已发布表仍可查看。

本地开发（不用 Docker）：

```bash
pip install -r requirements-dev.txt
pytest                      # 运行自测（53 个用例）
uvicorn app.main:app --reload --port 8000
```

## 使用流程

1. **上传**：在“上传”页选择检验 CSV。
2. **预览**：校验通过后生成安全表预览（隐藏格显示为“—”），
   同时**留存原 CSV 的 SHA-256 指纹**并展示在预览页；
   确认前可重新上传替换预览（换稿即作废旧核验结论），或放弃。
3. **核验**：在预览页重新上传**原件 CSV**（须与生成预览时上传的文件
   完全一致）和**登记台账 CSV**（独立登记台账，列格式相同），
   系统逐号比对并给出通过/未通过结论与差异明细（见下节）。
4. **确认发布**：仅当**原件指纹匹配当前预览且两侧逐号一致**
   （核验通过绑定当前预览版本）时，“确认发布”才会生效，原子写入 SQLite。
   **确认后不再接受替换文件**（上传接口返回 409）。
5. **查看**：已发布页 `/published` 随时可查，重启后仍在。

任何失败（CSV 校验失败、同号冲突、无法安全发布、核验未通过）都不会产生
部分公开结果：不展示表格、不改变已有状态。

## 逐号核验规则

- 原件、台账两份 CSV 均须含 `检验号,病区,周次,是否阳性` 四列；
  **各自按检验号去重**，同号内容冲突则该份**整份拒绝**（核验失败）。
- 通过条件（缺一不可）：
  1. 重新上传的原件指纹（SHA-256）与预览时留存的原 CSV 指纹一致；
  2. 两份文件各自解析通过；
  3. 两侧检验号集合一致，且同号记录的字段（病区/周次/是否阳性）无差异。
- 未通过时，核验页面列出：**仅原件/仅台账存在的检验号**、
  **同号字段差异明细**（检验号、字段、两侧取值）。
  差异明细只留在核验页面（`/verify`），**不进入发布表**。
- 同一预览版本**再次核验失败会撤销旧的通过结论**；核验进行中不能发布。
- 核验结论绑定预览版本：**换稿后旧结论不能放行新稿**；核验交错时，
  迟到的旧结论不落库、不覆盖较新的核验。
- 核验结论持久化在 SQLite：失败或重启后，仍只能发布当前核对通过的预览。

## CSV 格式

首行为表头，须包含四列（UTF-8，可带 BOM）：

```csv
检验号,病区,周次,是否阳性
A001,内科,2026-W44,是
A002,内科,2026-W44,否
A003,外科,2026-W45,阳性
```

- `是否阳性` 可填：是/否、阳性/阴性、1/0、true/false、y/n。
- 上传生成安全表时，文件须覆盖 **2～3 个病区、2～3 个周次**
  （按全部记录计，含阴性）；核验用的原件/台账不做此项限制，只逐号比对。
- **同一检验号**内容完全相同的记录只计一次；内容冲突（病区/周次/
  阴阳性任一不同）则**整份拒绝**。
- 交叉表统计各“病区 × 周次”的**阳性**检验数（按检验号去重）。

示例文件见 `samples/`：`ok_3x3.csv`（可发布）、`conflict.csv`
（同号冲突，拒绝）、`unpublishable_2x2.csv`（2×2 含小格，无法发布）。

## 保密规则

- 计数为 **1～2** 的格必须隐藏（一次隐藏）。
- 可**连带隐藏**其他格，但结果必须满足：
  1. 每行、每列至少保留一个公开格；
  2. 在“公开格取值 + 行合计 + 列合计”已知的前提下，每个隐藏格
     **至少有两种非负整数可行取值**（不能被行列合计唯一倒推）。
- 不存在满足条件的隐藏方案时，判定**无法发布**，仅提示原因。

实现要点（`app/suppression.py`）：隐藏格视为 ≥0 整数变量，公开格固定，
行列合计公开；二维列联表给定边际合计的可行性是运输问题，用最大流
（整数容量 ⇒ 整数解）精确判定；每个隐藏格的可行取值区间通过对上/下界
二分求得，区间宽度 ≥1 即满足“至少两种取值”。隐藏方案按连带隐藏格数
最少优先（对子集做 BFS，3×3 至多 2⁹ 个子集）。

注意：不足 3 行或不足 3 列的表，只要存在小格就无法发布——任何隐藏格
都会被其所在行/列的合计与其余公开格唯一确定，而再连带隐藏就会使某
行/列没有公开格。

## 目录结构

```
app/
  main.py          FastAPI 路由与流程（上传/预览/核验/确认/查看）
  csv_import.py    CSV 解析、校验、去重、冲突检测、交叉表
  verify.py        原件×台账逐号比对与差异明细
  suppression.py   保密隐藏规则与最大流可行性判定
  db.py            SQLite 持久化（pending+version / verification /
                   publication，原子发布，核验结论绑定预览版本）
  templates/       Jinja2 页面
  static/style.css
tests/             pytest 自测（隐藏规则 / CSV / Web 全流程 / 逐号核验）
samples/           示例 CSV
Dockerfile, docker-compose.yml
```
